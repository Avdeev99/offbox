# Hetzner baseline: 2026-10-23

This manually approved run exercised real provisioning and both sample applications. All test resources were deleted and the cloud inventory returned to its initially empty state. This is a small diagnostic baseline, not a performance guarantee or a paid CI job. [Measurements and individual latency samples](2026-10-23-hetzner.json) are sanitized; credentials and Terraform state are excluded.

## Setup

- Client: macOS 15.7.3 arm64, Python 3.12.7, Terraform 1.12.1, Mutagen 0.18.1.
- Host: Hetzner CPX32 in Helsinki (`hel1`), 4 vCPU / 8 GB, Ubuntu 24.04, kernel 6.8.0-138-generic, Docker 29.9.2.
- Each sample environment: 1 CPU and 2 GiB memory. FastAPI/Postgres and Vite/Playwright used separate Git repositories and isolated Docker daemons on the same VM.
- Universal image: `ghcr.io/o-avdieiev/offbox-universal@sha256:b8a57d964220ed595bc54fea2bc34327c97401a7b8df1aab9f129f25a88e68b1`.
- Code: `51fbcea` plus the bootstrap SSH refresh fix described below. The optional CLI timing summary was added after these measurements.

No client geography or Internet route was independently verified. Region comparisons require another measurement; this run alone cannot separate distance from provider performance.

## Correctness finding

The first VM bootstrapped in 111.46 s but app startup failed on Docker socket permissions. Readiness polling had authenticated before bootstrap added the `offbox` account to the Docker group. OpenSSH reused that login's old supplementary groups after bootstrap completed.

Host creation now closes that early SSH master, opens a fresh login and verifies Docker access before marking the host ready. Regression coverage also verifies that a failed Docker probe leaves recoverable initialization state. The second real-cloud run passed with this fix. The local Docker smoke fixture seeds its host registration and could not expose this cloud-bootstrap ordering.

## Resources, billing and cleanup

There were 152 resource samples at approximately three-second intervals. The largest sampled host memory use (`MemTotal - MemAvailable`) was 1.26 GiB; minimum available memory was 6.31 GiB. Sampled outer-container memory peaks were 278.8 MiB for Python and 381.3 MiB for Node. Final outer-container inspections reported `OOMKilled=false`. These observations are not an OOM test and can miss brief peaks.

The live account pricing API quoted USD 0.0673/hour for the VM and USD 0.001/hour for primary IPv4. Two sequential, short-lived attempts each round to one hour: **estimated USD 0.1366 total**, pending the invoice. Overall elapsed time across both attempts and diagnosis was 14.40 minutes. [Hetzner billing](https://docs.hetzner.com/general/billing-and-account-management/billing-at-hetzner/payment-overview/) rounds usage to full hours; it is not per-minute billing.

After each attempt, separate API checks confirmed zero servers, primary IPs, firewalls, volumes, floating IPs and SSH keys, matching the empty baseline. Mutagen sessions and the test daemon were stopped, and the temporary SSH Include was removed. No tokens or private keys appear in the measurement artifacts. Sensitive provisioning workspaces were kept outside the repository and removed by host destruction.

## Improvement priorities

1. Fix bootstrap connection freshness: completed and verified on the second VM.
2. Expose opt-in stage timing through `offbox --timings up` and `offbox --timings exec -- COMMAND`, while retaining parseable stdout and exit codes.
3. Batch dependency hash/marker reads and port-discovery metadata to reduce SSH round trips. Keep fresh ownership, sync, dependency and forwarding checks; avoid trusting cross-command cached metadata.
4. Compare a nearby region using the same workload and distinguish region effects from code changes. A different provider by itself does not guarantee lower latency.
5. Investigate cold dependency/image downloads and repeated setup in `up` separately from warm command latency. Preserve explicit fresh/reset and installation semantics until a measured change is justified.

Samples are small; nearest-rank p95 is the largest observation for these sample counts. No load, OOM stress, large-repository or production-workload claims follow from this run. The SSH/Docker baseline was sampled while the other app was running. CI remains unit/static/build validation plus the free Docker/SSH smoke job; this manual run adds no recurring paid tests.
