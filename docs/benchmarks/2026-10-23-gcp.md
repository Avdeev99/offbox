# Google Cloud and command batching: 2026-10-23

Both sample applications passed on one temporary Google Cloud VM. All test resources were deleted, and an independent API inventory matched the pre-test resources. This manually authorized run adds no paid CI. [Sanitized measurements and individual samples](2026-10-23-gcp.json) exclude credentials, project identifiers, private paths and Terraform state.

## Setup and comparison method

- Client: macOS 15.7.3 arm64, Python 3.12.7, Terraform 1.12.1, Mutagen 0.18.1.
- Host: `e2-standard-4`, Virginia `us-east4-c`, 4 vCPU / 16 GiB, AMD Rome, 50 GB balanced persistent disk, Ubuntu 24.04, Docker 29.9.2.
- Each sample environment: 1 CPU and 2 GiB; separate repositories and isolated inner Docker daemons, using the same universal image as the [Hetzner baseline](2026-10-23-hetzner.md).
- Improved client: `6305b7c` plus the GCP provider. Baseline client: a preserved wheel with the same bootstrap fix and timing support, before dependency/port batching. Both use Python 3.12.7 and the same locked runtime dependencies.
- Twenty old/new pairs ran on the same VM and Python application; order reverses on odd iterations. This isolates batching from region and VM changes. Other measurements use the improved client.

The previous Hetzner VM was in Helsinki with 8 GB RAM and a different disk. Cross-cloud results combine location, hardware, software and ordinary run variation; they cannot establish a provider-only speed advantage. Client geography and routing were not independently verified.

## Interaction latency

Durations are seconds, including client startup and temporary instrumentation. p95 uses nearest rank.

| Operation | Samples | Median | p95 |
| --- | ---: | ---: | ---: |
| Local Python no-op | 20 | 0.012 | 0.013 |
| Local Offbox version | 20 | 0.120 | 0.126 |
| New SSH connection, no multiplexing | 3 | 0.505 | 0.525 |
| Warm multiplexed SSH `true` | 20 | 0.072 | 0.075 |
| Warm SSH + direct Docker `exec true` | 20 | 0.144 | 0.152 |
| Full Python `exec true`, before batching | 20 | 1.213 | 1.402 |
| Full Python `exec true`, after batching | 20 | 1.065 | 1.195 |
| Python `exec --no-sync true`, after batching | 10 | 0.995 | 1.186 |
| Full Node `exec true`, after batching | 5 | 0.978 | 1.031 |
| Small-file write + `exec cat` verifies sync | 5 | 1.007 | 1.184 |
| Forwarded API health request | 20 | 0.076 | 0.079 |

Batching reduced the median full command by **0.148 s, or 12.2%**, on the same GCP host. Fresh dependency hashing, installation-marker validation, container ownership/running checks and forwarding checks still execute. Four sequential remote operations remain, including the command itself; no cross-command metadata cache was introduced.

The previous Helsinki run measured 0.272 s warm SSH and 2.928 s full commands. Virginia measured 0.072 s SSH even before attributing any benefit to client changes. The larger cross-run difference therefore cannot be credited to batching alone.

For improved Python no-ops, median phases were 0.096 s sync flush, 0.124 s dependency checks, 0.372 s port discovery/restoration, and 0.181 s final command/completion. These exclude startup and some preflight work. Port discovery is the largest measured warm phase and is a useful next profiling target.

The 10 MiB random-file sync and remote SHA256 check took **2.28 s**. Remote file write through Offbox followed by local sync took **1.01 s**. Three source edit/restore cycles became visible over HTTP in **2.68–3.01 s**. Hot reload therefore remains slower than command execution; network latency alone does not explain it.

## Correctness and resource observations

Python API/Postgres tests passed in 5.33 s initially, 2.61 s after resume, and 2.69 s after source reload checks. Chromium passed in 4.61 s initially and 4.38 s after resume. The frontend production build passed in 1.65 s. These are CLI totals, rather than test-runner-only durations.

A synthetic database row survived stop/start; `--fresh` removed it while preserving synchronized source. Both forwarded applications responded locally. Remote exit codes 42 and 255 were preserved. A custom benchmark lookup initially compared macOS `/var` and `/private/var` paths literally. The harness was corrected to resolve paths, and the remaining Python checks completed against the same VM. The failed lookup and diagnostic pause are excluded from latency distributions; they were not an Offbox failure.

There were 109 resource samples. Maximum sampled host memory use was 1.52 GiB, minimum available memory 14.09 GiB, and minimum available disk 38.69 GiB. Sampled outer-container memory peaks were 294.0 MiB for Python and 364.8 MiB for Node. Final inspections reported `OOMKilled=false`. Sampling can miss brief peaks, and this was not a stress test.

## Billing, credentials and cleanup

The public Google billing catalog quoted Virginia E2 CPU at $0.02456745/vCPU-hour and RAM at $0.00329199/GiB-hour: **$0.15094164/hour** for this VM. The 50 GB balanced disk is $5.50/month, with external IPv4 up to $0.005/hour before applicable free allowances. Using the entire 594.28-second harness interval, which exceeds resource lifetimes, gives a conservative **$0.02696 compute/disk/IP estimate**. Network egress, Secret Manager/API operations, credits, discounts and taxes are excluded; this is not an invoice. See [Compute billing](https://cloud.google.com/products/compute/pricing), [disk pricing](https://cloud.google.com/compute/disks-image-pricing) and [network pricing](https://cloud.google.com/vpc/network-pricing).

Authentication used a dedicated provisioning service account and a short-lived impersonated OAuth token stored in Secret Manager. No service-account private key was generated. The VM API confirmed that no service account was attached to the development host. The provisioning identity and requested secret remain for reuse; the access token expires and is not a permanent credential. See [Google authentication](https://docs.cloud.google.com/docs/terraform/authentication) for repeat-use ADC/impersonation setup.

Independent checks found zero test instances, disks, addresses, firewalls, subnets, networks or routes. Original resource IDs were preserved and final inventory matched the baseline. Test Mutagen sessions/daemon and the temporary SSH Include were removed. Credentials and private SSH host keys were checked absent from measurement artifacts. CI uses deterministic unit/static/build checks, mocked Terraform contracts and the existing free Docker/SSH smoke job.
